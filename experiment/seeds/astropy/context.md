# Repository Context

## Intent
Astropy is a community Python library for astronomy whose core value is a set of composable, type-safe primitives (tables, arrays with physical units) plus a pluggable I/O layer that lets any core class gain uniform `read`/`write` methods across many file formats. Two design philosophies dominate the areas below. First, I/O is decoupled from data classes via a central *unified registry*: format readers, writers, and identifiers are registered as `(format, class)` pairs at import time, and dispatch resolves the correct callable by format string or by sniffing the input. Second, physical correctness is enforced structurally: `Quantity` subclasses `numpy.ndarray` and carries a `Unit`, so arithmetic, unit conversion, and equivalencies are handled by intercepting NumPy's ufunc machinery rather than by convention. Both subsystems favor lazy, view-based, import-time-registered behavior over runtime configuration.

## Constraints

### io registry and format contract
- The registry lives in `astropy/io/registry.py` as module-level `OrderedDict`s `_readers`, `_writers`, `_identifiers` keyed by `(data_format, data_class)`. `register_reader`/`register_writer`/`register_identifier` refuse to overwrite an existing key unless `force=True`, raising `IORegistryError`; per-format wiring belongs in each subpackage's `connect.py` (e.g. `astropy/io/fits/connect.py:392-394` registers `'fits'` reader, writer, and `is_fits` identifier for `Table`).
- Class resolution is inheritance-aware via `_is_best_match` (`registry.py:565`): a registered entry matches a requested class only if it is the *nearest* registered ancestor in the MRO. Registering a base class (e.g. `Table`) makes subclasses inherit its I/O, but registering an intermediate class shadows the base for that branch — respect this when adding entries.
- Identifier functions (`identify_format`, `registry.py:379`) receive `(origin, path, fileobj, *args, **kwargs)` where `origin` is `"read"`/`"write"`; one or both of `path`/`fileobj` may be `None`, so an identifier must fall back to `args[0]`. `_get_valid_format` (`registry.py:588`) requires *exactly one* identifier to match: zero matches or two-plus both raise `IORegistryError`, so new identifiers must be mutually exclusive with existing ones for the same class.
- `read` (`registry.py:480`) opens path arguments in binary via `get_readable_fileobj`, coerces `pathlib.Path` to `str`, and if a reader returns a parent class it attempts `cls(data)` coercion — a reader must return an instance of (a superclass of) the requested class or `TypeError` is raised. `write` (`registry.py:539`) does not open the file; the writer owns the path.
- Registering also rebuilds docstrings via `_update__doc__`, which is expensive; bulk registration should be wrapped in the `delay_doc_updates(cls)` context manager (`registry.py:41`) that suppresses rebuilds until exit. `get_formats` drives both the docstring tables and user-facing format listings.

### units and quantities
- `UnitBase` and its subclasses (`NamedUnit`, `IrreducibleUnit`, `Unit`, `PrefixUnit`, `CompositeUnit`) live in `astropy/units/core.py`. Unit *identity* matters: `_to`/`_get_converter` (`core.py:871,901`) short-circuit when `self is other` and otherwise compare `decompose()`d bases/powers by object identity, so canonical unit singletons must not be duplicated. Conversion returns a *converter closure*, not a scaled value.
- Enabled units are held in a per-thread `_UnitRegistry` accessed through `get_current_unit_registry`; `set_enabled_units`/`add_enabled_units` (`core.py:152,171`) mutate the name→unit map and reject conflicting redefinitions. `_UnitContext` (`core.py:264`) makes enablement stack-scoped — changes must go through these paths, never by mutating the dict directly.
- `Quantity` (`astropy/units/quantity.py:200`) is a `numpy.ndarray` subclass. `__new__` (`quantity.py:274`) normalizes `unit` via `Unit(...)` and, with `subok=True`, may upgrade `cls` to a unit's `_quantity_class`. `__array_finalize__` propagates the `unit` across views/slices, so any new instance attribute must be handled there or it will be lost on slicing.
- All unit-aware arithmetic flows through `__array_ufunc__` (`quantity.py:597`): it asks `converters_and_unit` (in `astropy/units/quantity_helper.py`) for per-input converter callables and the result unit, converts inputs to plain arrays, calls `super().__array_ufunc__`, then re-wraps via `_new_view`/`_result_as_quantity`. A `unit` of `None` signals a bare-array result (e.g. comparisons). New ufunc support means adding a helper to `quantity_helper.py`'s `UFUNC_HELPERS`, not special-casing the method.
- `.to(unit, equivalencies=[])` (`quantity.py:821`) always copies via `_new_view`; the `equivalencies` default `[]` means "use class defaults" while `None` means "disable all equivalencies (even global/context ones)" — preserve this three-state semantics. Equivalencies are applied in `_apply_equivalencies` (`core.py:822`) and unit string parsing lives in the pluggable parsers under `astropy/units/format/` (generic, fits, cds, ogip, vounit).
