# Repository Context

## Intent
SymPy is a pure-Python computer algebra system in which every mathematical object is an immutable `Basic`/`Expr` tree, and every derived textual or transformed form is produced by a separate visitor rather than by the objects themselves. Two subsystems dominate the topics here. Printing (`sympy/printing/`) is a family of visitor `Printer` subclasses that walk the same expression tree to emit `str`, `repr`, LaTeX, pretty (2D), MathML, and target-language code; the deliberate architectural choice (documented in `printer.py`'s module docstring) is that printing logic is centralized in printers, not scattered as per-class methods, so that a printer produces uniform, high-quality output across all node types. Simplification (`sympy/simplify/`) is a collection of independent, well-defined rewrite functions (`powsimp`, `radsimp`, `trigsimp`, `cancel`, `together`, ...) plus one heuristic orchestrator, `simplify()`, that chains them and keeps a result only if it measures "simpler." The governing philosophy in both areas is correctness and consistency over cleverness: transformations must preserve mathematical value, and printers must render structurally identical inputs identically.

## Constraints

### printing and LaTeX output consistency
- Dispatch is uniform across all printers via `Printer._print` in `sympy/printing/printer.py` (lines 235-262): it first honors an object's own `printmethod` (`_latex`, `_sympystr`, ...) if present, else walks `type(expr).__mro__` calling `_print_<ClassName>`, else `emptyPrinter`. A new `_print_Foo` must live on the printer class, respect this MRO fallback (a `_print_Base` covers subclasses), and never mutate `expr`.
- Bracketing must go through precedence, not ad-hoc string tests. `sympy/printing/precedence.py` defines `PRECEDENCE`, `PRECEDENCE_VALUES`, and `precedence()`; `precedence_traditional()` (lines 123-135) raises `Integral`/`Sum`/`Product`/`Limit`/`Derivative` to `Mul` precedence for LaTeX and pretty printers only. `LatexPrinter.parenthesize` (`latex.py:148`) and `StrPrinter.parenthesize` (`str.py:27`) both compare `precedence(item)` against a level with a `strict` flag; changes to bracketing belong in these tables, and str vs. LaTeX precedence must stay reconciled.
- `latex.py` `_print_Mul` (line 329) and `_print_Add`/`_print_Pow` are the consistency hotspots: negative coefficients are pulled out via `_coeff_isneg`, numerator/denominator are split by `fraction(exact=True)`, and `mul_symbol`, `fold_short_frac`, `long_frac_ratio`, `fold_frac_powers` settings gate output shape. Any edit here must keep `_needs_mul_brackets`/`_needs_brackets` (lines 168+) in agreement so `-x`, `a+b`, and rationals are wrapped identically to their str/pretty forms.
- Symbol name rendering is shared: `sympy/printing/conventions.py` `split_super_sub` parses `_`/`^`/`__` into name/supers/subs and treats trailing digits as subscripts. LaTeX layers `tex_greek_dictionary`, `greek_letters_set`, `modifier_dict`, and `accepted_latex_functions` (`latex.py:32-99`) on top; renaming or reformatting a symbol must go through these tables so pretty and LaTeX stay in lockstep.
- Printer settings are validated in `Printer.__init__` (`printer.py:196-215`): unknown keys raise `TypeError`, and every new setting must be added to the subclass `_default_settings` (LaTeX at `latex.py:104`, str at `str.py:20`). Float/number formatting honors `full_prec` and `_print_level`; code printers (`codeprinter.py`) additionally collect `_not_supported`/`_number_symbols` and must emit valid target-language tokens rather than SymPy repr.

### expression simplification correctness
- `simplify()` in `sympy/simplify/simplify.py` (def at line 384; body ~505-615) is a heuristic pipeline, not a canonicalizer: it first tries `expr._eval_simplify`, records `original_expr = signsimp(expr)`, then chains `powsimp`, `cancel`, `together`, `factor_terms`, `hyperexpand`, `trigsimp`, `combsimp`, `radsimp`, etc. A `shorter(*choices)` helper picks the fewest-`count_ops` form, and the final `if measure(expr) > ratio*measure(original_expr)` guard (default `ratio=1.7`) reverts to input. Never assume `simplify` output is unique or minimal; adding a step must preserve this size guard and the value of the expression.
- Prefer editing the specific, well-defined functions over `simplify()` itself: `powsimp.py`, `radsimp.py` (`radsimp`, `fraction`), `ratsimp.py`, `trigsimp.py`, `combsimp.py`, `sqrtdenest.py`, `hyperexpand.py`. `simplify()`'s docstring explicitly directs callers to these because they have defined contracts; a correctness fix usually belongs in the sub-function so all callers benefit.
- Trig simplification is layered: `trigsimp` (`trigsimp.py:428`) selects a method and `simplify()` gates it on `expr.has(TrigonometricFunction)` and the `fu` flag, delegating to Fu's rule transforms `TR0..TRxx`/`CTR1..4` and `futrig` in `sympy/simplify/fu.py`. These rules must hold for all admissible assumptions; a rule valid only for real/positive arguments must guard on the relevant `is_*` assumption or it introduces incorrect identities.
- Structural traversal uses `bottom_up(rv, F)` (`simplify.py:919`), which rebuilds a tree by applying `F` to each node from the leaves up. Callbacks must return value-equivalent nodes and tolerate any node type, since `bottom_up` is used to normalize before the heavy rewrites; a callback that assumes a specific `func` will corrupt unrelated subtrees.
- Sign handling threads through `signsimp` (`simplify.py:322`), `_coeff_isneg`, `could_extract_minus_sign()`, and the closing `signsimp(-n/(-d))` step. Because these decide whether `-a/(-b)` and `a/b` converge, changes must keep sign normalization idempotent and consistent with how the printers detect negativity, so a simplified result and its printed form agree.
