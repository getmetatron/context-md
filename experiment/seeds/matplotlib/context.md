# Repository Context

## Intent
Matplotlib is a plotting library whose core discipline is separating *user data* (which may carry units, be categorical, or be datetimes) from the *scalar float* space the drawing and autoscaling machinery actually operates on, and separating *scalar data* from the *RGBA colors* rendered on screen. Two pluggable pipelines embody this. The unit pipeline (`lib/matplotlib/units.py`) lets arbitrary object types register a converter so they can be plotted natively, with the `Axis` mediating conversion, tick locators/formatters, and default limits. The color pipeline runs `data -> Normalize -> Colormap -> RGBA` (`lib/matplotlib/colors.py`, `lib/matplotlib/cm.py`), where a `Normalize` scales data into `[0, 1]` and a `Colormap` looks that up in a quantized lookup table. Both pipelines are registry-driven, lazy, and stateful, so the durable risks are ordering, caching, and float-domain assumptions.

## Constraints

### unit and axis handling
- The converter contract lives in `lib/matplotlib/units.py`: a converter subclasses `ConversionInterface` and supplies `convert(obj, unit, axis)`, `axisinfo(unit, axis)` returning an `AxisInfo` (locators, formatters, label, `default_limits`), and `default_units(x, axis)`. Types are mapped to converters through the module-global `registry` (a `Registry(dict)`); `dates.py` (lines ~2071-2073) and `category.py` (lines 223-226) install their converters at import time, so importing those modules has the side effect of enabling conversion for their types.
- `Registry.get_converter` (units.py:139) does more than a dict lookup: it unwraps pandas `.values`, drills into `np.ma.getdata(...).ravel()`, infers by dtype for empty arrays, and recurses into the first element for sequences (guarding against pathological self-returning iterables). Changes here must preserve empty-array and masked-array handling and the recursion guard.
- The `Axis` (`lib/matplotlib/axis.py`) owns `self.converter` and `self.units`. `update_units` (1486) refreshes the converter and only calls `_update_axisinfo` when the converter actually changes; `_update_axisinfo` (1508) reinstalls locators/formatters/label *only* while the corresponding `isDefault_*` flags hold, so user-set ticks are never clobbered. `convert_units` (1545) short-circuits when `is_numlike`, so already-numeric input bypasses conversion — a key invariant to keep.
- `Axes._process_unit_info` (`lib/matplotlib/axes/_base.py`:2086) is the entry point plotting methods call; it only updates a unit if the axis does not already `have_units()`. Mixing categorical and numeric data on one axis is a documented hazard: `StrCategoryConverter.convert` (category.py) raises if the `UnitData` unit is missing.
- Pitfall: the whole pipeline assumes conversion yields floats the datalim/autoscale/locator layer can consume; converters must return numlike scalars/arrays, and `set_units` (axis.py:1562) fires `'units'`/`'units finalize'` callbacks whose listeners expect a fully reconverted axis. Do not conflate `units` (a tag) with `converter` (behavior); either alone makes `have_units()` true.

### colormap and normalization
- `Normalize.__call__` (`lib/matplotlib/colors.py`:902) is the scaling contract: it runs `process_value` (872) to homogenize input into a masked array (int<=2 bytes -> float32, larger -> float64, floats preserved), calls `autoscale_None` to lazily fill `vmin`/`vmax` from the first data seen, and maps `[vmin, vmax] -> [0, 1]`. Invariants: `vmin==vmax` returns 0, `vmin>vmax` raises, and it operates in-place on `result.data` for speed. Subclasses (`LogNorm` 1038, `SymLogNorm`, `PowerNorm`, `BoundaryNorm`, `DivergingNorm`) must keep `__call__`/`inverse`/`autoscale`/`autoscale_None` mutually consistent — e.g. `LogNorm` masks non-positive values and requires `vmin>0` (`_check_vmin_vmax`).
- `Colormap.__call__` (colors.py:438) converts normalized floats to RGBA via a lookup table (`self._lut`), which is built lazily by `_init` (subclass-specific) guarded by `_isinit`. Out-of-range handling is index-based: entries `_i_under`, `_i_over`, `_i_bad` sit at `N`, `N+1`, `N+2`; float inputs are scaled by `N` with careful clamping (`xa==N -> N-1`, negatives -> -1) — this arithmetic is fragile and must not truncate out-of-range values toward zero.
- Under/over/bad colors (`set_under`/`set_over`/`set_bad`, colors.py:534-566) only take effect through `_set_extremes` after `_isinit`; crucially they require `norm.clip=False`, since clipping (Normalize `clip=True`) folds out-of-range data to 0/1 and silently defeats them.
- The colormap registry is `cm.cmap_d` (cm.py:33), populated at import from `_cm`/`_cm_listed` and exposed via `get_cmap` (155) and `register_cmap` (116). `get_cmap(name, lut)` returns a `_resample(lut)` copy when `lut` is given; every `Colormap` subclass must implement `_resample` (base raises `NotImplementedError`, colors.py:578). Do not mutate cached cmap instances in place.
- `ScalarMappable` (`lib/matplotlib/cm.py`:180) binds a `norm` and `cmap` and drives `to_rgba` (217): 3-D arrays with last dim 3/4 are treated as pre-formed RGB(A) and bypass normalization entirely, otherwise `x = self.norm(x)` then `self.cmap(...)`. `set_clim` (309) writes `norm.vmin/vmax` (sanitized) and calls `changed()`; changing clim or norm must invalidate downstream state, and float RGB image values are required to stay in `[0, 1]`.
