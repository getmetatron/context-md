# Repository Context

## Intent
scikit-learn is a machine-learning library whose defining architectural discipline is a uniform, duck-typed estimator API layered on top of a centralized input-validation stack. Estimators are plain Python objects that expose their hyperparameters as `__init__` keyword arguments and their learned state as trailing-underscore attributes; behavior is composed through mixins rather than a deep inheritance hierarchy. Two concerns dominate any change in this area. First, the *estimator API contract* — the introspectable, cloneable, get/set-params protocol implemented in `sklearn/base.py` and machine-verified by `sklearn/utils/estimator_checks.py` — must hold for every estimator so that meta-estimators (pipelines, grid search, ensembles) can treat estimators interchangeably. Second, *input validation* is factored into a single reusable toolkit in `sklearn/utils/validation.py`, so estimators coerce and check `X`/`y` consistently instead of reimplementing checks. Respecting both contracts is what makes estimators composable and their errors uniform.

## Constraints

### estimator API contract
- Core protocol lives in `sklearn/base.py`: `BaseEstimator._get_param_names` (base.py:153) introspects `__init__` via `inspect.signature`; it raises `RuntimeError` on `*args`/`VAR_POSITIONAL`. Hard rule: `__init__` must list every hyperparameter as an explicit keyword, must not accept `*args`/`**kwargs`, and must store each argument on `self` unchanged — `clone` (base.py:35) reconstructs an estimator from `get_params` and raises `RuntimeError` if a param "is not set or is modified" by the constructor.
- Learned state must live in attributes ending with `_` (e.g. `coef_`, `labels_`), set only during `fit`; `fit` must return `self`. Estimator "kind" is declared by the class attribute `_estimator_type` ("classifier"/"regressor"/"clusterer"/"outlier_detector") set on the mixins in base.py:339–611 and read by `is_classifier`/`is_regressor` (base.py:632).
- Capabilities are declared via tags, not overridden methods: `_DEFAULT_TAGS` (base.py:18) plus per-class `_more_tags`, merged by `_get_tags` (base.py:323) using `_update_if_consistent`, which raises `TypeError` on conflicting tag values across the MRO. Tags (`allow_nan`, `no_validation`, `multioutput`, `requires_fit`, `X_types`, ...) drive which conformance checks run — changing validation behavior usually means also setting the matching tag.
- The contract is enforced by `sklearn/utils/estimator_checks.py`: `check_estimator` (estimator_checks.py:290) runs the `_yield_*` check suites. Meta-estimators declare `_required_parameters` (see `MetaEstimatorMixin` in base.py:614) so the harness can instantiate them; new estimators must pass these checks rather than only working in isolation.
- `set_params`/`get_params` (base.py:180–246) implement nested access via the `<component>__<param>` dunder convention; `set_params` rejects unknown keys with `ValueError`. `__getstate__`/`__setstate__` (base.py:297) stamp `_sklearn_version` for cross-version unpickle warnings — pickle compatibility is part of the contract.

### input validation
- All coercion funnels through `sklearn/utils/validation.py`. `fit`/`predict` implementations must call `check_X_y` (validation.py:602) or `check_array` (validation.py:334) rather than trusting raw input; `estimator_checks.py` explicitly tells authors to "use check_X_y/check_array in fit" (e.g. estimator_checks.py:1513, 1911).
- `check_array` invariants: default `dtype="numeric"` preserves dtype but converts object arrays to `float64`; `ensure_2d=True` rejects scalar/1-D input with the canonical "Reshape your data" message (validation.py:509–523); `allow_nd=False` rejects ndim≥3; `ensure_min_samples`/`ensure_min_features` reject empty data. Complex data is always rejected via `_ensure_no_complex_data` (validation.py:327). Changing any default silently alters every caller.
- Finiteness is governed by `force_all_finite` (True / False / 'allow-nan') dispatched to `_assert_all_finite` (validation.py:35), which honors the global `assume_finite` config and, for object dtype, only checks NaN. An estimator that tolerates NaN must both pass `force_all_finite='allow-nan'` and set the `allow_nan` tag — otherwise conformance checks (estimator_checks.py:95) will contradict runtime behavior.
- Sparse input is opt-in: `check_array(accept_sparse=...)` routes to `_ensure_sparse_format` (validation.py:236); `accept_sparse=False` raises `TypeError` telling users to densify, a non-listed format is converted to the first listed format, and 64-bit indices are rejected by `_check_large_sparse` (validation.py:583) unless `accept_large_sparse=True`.
- Target handling: `check_X_y` raises on `y=None`, validates `X` then `y` (as `column_or_1d` with a `DataConversionWarning` for column vectors, or a 2-D CSR array when `multi_output=True`), and enforces equal sample counts via `check_consistent_length` (validation.py:192). Companion helpers — `check_is_fitted` (validation.py:869, raising `NotFittedError`), `_check_sample_weight` (validation.py:989), `check_random_state`, `column_or_1d`, `check_non_negative` — are the sanctioned checks; reuse them instead of inlining equivalents.
